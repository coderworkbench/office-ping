# Chat messenger: design

Date: 2026-10-24
Status: approved in brainstorming, awaiting spec review

## Goal

Add one-to-one text chat to Office Ping, modelled on LinkedIn's messaging
dock: a collapsible panel in the bottom-right corner on desktop with a chat
list and small conversation windows, and a full-screen Messages section on
phones.

Chat is the *quiet* channel. Pings stay the loud one (centre pop-up, chime,
acknowledgement). Chat never opens an in-app pop-up, never plays a sound and
never breaks through Do Not Disturb.

## Decisions

| Topic | Decision |
|---|---|
| Scope | One-to-one chat only. The data model supports group chats so they can be added later without migrating existing chats. |
| Privacy | Only the two participants can read messages. The audit log records that a chat was started, never message text. No HR/admin reading view. |
| Content | Plain text up to 4,000 characters. Emoji via the OS emoji keyboard. http/https links are clickable. No attachments. |
| Extras in v1 | Read receipts ("Seen"), typing indicator, desktop notifications for new messages. |
| Not in v1 | Group chats, attachments, editing/deleting messages, full-text search of message bodies, HR access, retention policy. |
| Transport | Send over REST; push to browsers over the existing `/ws/notifications/` socket. Only typing events go from browser to server over the socket. |
| Retention | Messages are kept indefinitely, like pings. |

## Backend

### New app: `apps/chat`

Separate from `apps/notifications` so ping and chat logic stay independent.
It reuses `user_group_name()` from `apps.notifications.services` to reach a
user's connected devices.

### Models

**Conversation**
- `kind`: `DIRECT` (the only value in v1; `GROUP` reserved).
- `direct_key`: `"<smaller user id>:<larger user id>"`, unique, null for
  future group chats. Guarantees one conversation per pair.
- `created_at`
- `last_message_at`: nullable, indexed; sorts the chat list.

**ConversationMember**
- `conversation`, `user`; unique together.
- `last_read_message`: nullable FK to `Message` (`SET_NULL`). Drives unread
  counts and "Seen".
- `muted`: boolean, default false. Suppresses desktop notifications only;
  unread counts still update.
- Index on `(user, conversation)`.

**Message**
- `conversation`, `sender`, `body` (`TextField`, max 4,000 characters,
  validated in the serializer; leading/trailing whitespace stripped; empty
  after stripping is rejected).
- `created_at`
- Index on `(conversation, -id)`.

Message ids increase monotonically, so "unread" is
`messages where id > last_read_message_id and sender != me`.

### REST API (prefix `/api/chat/`)

All endpoints require authentication. A conversation the caller is not a
member of returns **404** (not 403), so its existence is not revealed.

| Method and path | Body / query | Result |
|---|---|---|
| `GET conversations/` | | Caller's conversations, newest `last_message_at` first (never-messaged ones last). Each item: `id`, `other` (id, name, department, `online`, `status` from `User.current_status()`, `is_active`), `last_message` (id, sender_id, body truncated to 140 chars, created_at) or null, `unread`, `muted`, `other_last_read_id`. |
| `POST conversations/` | `{user_id}` | Get-or-create the direct conversation with that user. 201 when created, 200 when it already existed. 400 for yourself or a deactivated/unknown user. |
| `GET conversations/<id>/` | | One conversation, same shape as a list item. |
| `GET conversations/<id>/messages/` | `?before=<message id>` | Up to 30 messages older than `before` (latest 30 when omitted), returned oldest-first, plus `has_more`. |
| `POST conversations/<id>/messages/` | `{body, client_id?}` | Creates the message, updates `last_message_at`, moves the sender's own read marker to it, broadcasts `chat.message`, returns the message (201). 403 if the other member is deactivated. Throttled. |
| `POST conversations/<id>/read/` | `{message_id}` | Sets the caller's `last_read_message` to `message_id` only if it is newer than the current one and belongs to this conversation. Broadcasts `chat.read` when it moves. Returns `{unread_total}`. |
| `POST conversations/<id>/mute/` | `{muted}` | Sets `muted`. |
| `GET unread/` | | `{unread_total}` across all conversations, for badges. |

`client_id` is an opaque string (max 64 chars) generated by the browser and
echoed in the broadcast so the sending tab can replace its optimistic bubble.

### Rate limiting

New DRF scope `chat_send`, default `30/minute`, overridable with `CHAT_RATE`
in `.env` (added to `.env.example`). Responses use the existing 429 shape so
the frontend can reuse its handling.

### Audit

New `AuditLog.Action.CHAT_STARTED`, recorded once when `POST conversations/`
creates a conversation. `target` is the other user's username; metadata holds
`conversation_id`. Message text is never written to the audit log. Needs a
migration on `audit` for the new choice.

### Django admin

Register `Conversation` and `ConversationMember`. Register `Message` without
`body` in `list_display`, `fields` or search, so message text is not casually
browsable in admin.

## Real-time

### Server to browser

Sent with `channel_layer.group_send(user_group_name(uid), …)` from a small
`apps/chat/broadcast.py`. `NotificationConsumer` gains three handlers that
forward the payload unchanged:

| Channel type | Socket message type | Recipients | Payload |
|---|---|---|---|
| `chat.message` | `chat_message` | both members | `{conversation_id, message: {id, sender_id, body, created_at}, client_id, quiet}` |
| `chat.read` | `chat_read` | both members | `{conversation_id, user_id, message_id}` |
| `chat.typing` | `chat_typing` | other member only | `{conversation_id, user_id}` |

`quiet` is computed per recipient: true when that recipient's
`wants_quiet` is true (In a meeting / Do not disturb). Because the payload
differs per recipient, `chat.message` is sent with one `group_send` per
member.

Broadcasting is best-effort: failures are logged and never fail the REST
request. The database is the source of truth.

### Browser to server

`{type: "chat_typing", conversation_id}` on `/ws/notifications/`. The
consumer checks the caller is a member (cached per connection in a set) and
forwards `chat.typing` to the other member. Non-members are ignored silently.
The browser sends at most one every 3 seconds while the composer has input.

### Delivery and recovery

- **Optimistic send:** the composer shows the message as "Sending…" with a
  `client_id`. The REST response or the `chat_message` echo (whichever comes
  first) replaces it. On failure it shows "Not sent · Retry".
- **De-duplication:** messages are keyed by `id` in the client store.
- **Reconnect:** when the socket reopens, the client refetches the
  conversation list, the unread total and the latest page of every open
  conversation.

## Notifications and Do Not Disturb

Handled in `NotificationsRuntime` on `chat_message`. A desktop notification
is shown only when all of these hold:

1. `message.sender_id` is not the current user;
2. the conversation is not muted (from the client's conversation store);
3. `quiet` is false;
4. the tab is hidden, or that conversation is not currently open and focused.

The notification:
- title is the sender's name, body is the message (truncated to 140 chars);
- `sticky: false` (not `requireInteraction`), no in-app pop-up, no sound;
- tag `chat-<conversation_id>`, so a burst of messages updates one
  notification;
- `data.url` is `/messages?c=<conversation_id>`;
- is closed via `closeNotification('chat-<id>')` when a `chat_read` arrives
  for the current user on that conversation (read on any device).

`sw.js` `notificationclick`: when `data.url` starts with `/messages`, focus
an existing window and navigate it to that URL (or open a new window).
Ping behaviour is unchanged.

The chat window header has a **🔔 Ping** button that opens the existing ping
composer with the other person preselected.

## Frontend

### Shared client state: `lib/chat.ts`

A small store (module-level, exposed via `useSyncExternalStore`, matching
`useLiveStatus` in `NotificationsRuntime`) holding conversations, messages per
conversation, typing state, unread total and open/focused conversation ids.
It exposes actions: `openConversation(userId)`, `loadOlder(id)`,
`send(id, body)`, `markRead(id)`, `setMuted(id, muted)`, `sendTyping(id)`.
`NotificationsRuntime` feeds socket events into it; the dock and `/messages`
page only read from it and call actions. Components never talk to the socket
directly.

### Components

- `components/chat/ChatDock.tsx`: desktop dock (≥1024px only), mounted in
  `AppShell`.
- `components/chat/ConversationList.tsx`: search box plus rows, shared by
  the dock and `/messages`.
- `components/chat/ConversationView.tsx`: header, message list and composer,
  shared by dock windows and `/messages`.
- `components/chat/Avatar.tsx`: initials avatar with presence dot (no photos
  exist in the user model).
- `app/messages/page.tsx`: two-pane on desktop, list then conversation on
  phones, driven by `?c=<id>`.

### Desktop dock

- Fixed bottom-right, 320px wide.
- **Collapsed bar:** current user's initials avatar with presence dot,
  "Messages", red unread badge, ✏️ new message (opens a person search based on
  `PersonSelect`), ⌃ toggle.
- **Expanded:** up to `min(70vh, 560px)` tall. A search box filters
  conversations by name. Rows show avatar and dot, name, time ("10:42" today,
  "Mon" this week, "Oct 21" older), a one-line preview ("You: …" for own
  messages), bold plus count when unread, and 🔕 when muted.
- **Conversation windows** open to the left of the dock, 336×460px. Up to two
  at ≥1280px and one below that; opening another closes the oldest.
  - Header: name, status line ("Online" / "In a meeting until 3:00 pm" /
    "Active 12 min ago"), 🔔 Ping, mute toggle, minimise, close.
  - Body: day dividers, own messages right in the gold accent, theirs left on
    surface, "Seen" under the last own message when
    `other_last_read_id >= its id`, a "typing…" row, older messages loaded on
    scroll to top.
  - Composer: auto-growing textarea up to 5 lines; Enter sends, Shift+Enter
    adds a newline. Disabled with a note when the other person is deactivated.
- An open, focused conversation marks itself read as new messages arrive.
- Dock expanded state and open windows persist in `localStorage` (wrapped in
  try/catch), so they survive reloads.
- `SenderToasts` and the `Tour` card move up above the dock bar on desktop.

### Phones and tablets (<1024px)

- No dock.
- The bottom tab bar becomes Overview, People, Inbox, **Messages** (with
  unread badge), More. History moves into the More sheet.
- `/messages` shows the conversation list full-screen; tapping opens the
  conversation full-screen with a ← back button. The composer stays above the
  on-screen keyboard using the same `visualViewport` approach as `MobileHome`.

### Navigation and entry points

- Desktop nav rail: a **Messages** item below Inbox, with the unread badge.
- **💬 Message** buttons next to **Ping** on the People page and in the person
  picker.
- ✏️ new message in the dock and on `/messages`.
- `/messages` added to the prefetch map in `AppShell` (`warm`).

## Error handling

| Case | Behaviour |
|---|---|
| Send fails (network, 5xx) | Bubble shows "Not sent · Retry"; text is kept. |
| 429 rate limit | Same as above with "Slow down a little" toast. |
| Other person deactivated | Composer disabled with "This person's account is deactivated." History stays readable. |
| Conversation not found (404) | `/messages?c=` falls back to the list; dock window closes. |
| Socket down | Existing "Live" badge reflects it; sends still work over REST; state resyncs on reconnect. |
| Broadcast failure | Logged server-side; recipient sees the message after the next refetch. |

## Testing

### Backend (pytest)

- Opening a conversation twice returns the same one (201 then 200);
  `direct_key` uniqueness holds; self and deactivated targets are rejected.
- Non-members get 404 on every conversation endpoint.
- Message pagination: `before` cursor, oldest-first order, `has_more`.
- Sending: body validation (empty, whitespace, >4,000 chars), `last_message_at`
  updated, sender's read marker moved, `group_send` called once per member
  with `client_id` echoed and `quiet` true for a recipient in DND/meeting.
  Uses an in-memory channel layer.
- Read marker never moves backwards and rejects ids from other conversations;
  unread counts per conversation and total are correct.
- `chat_send` throttle returns 429 past the limit.
- `CHAT_STARTED` audited exactly once per conversation, with no message text.
- Consumer (`WebsocketCommunicator`): typing reaches only the other member; a
  non-member's typing event is dropped; `chat.message` and `chat.read` events
  are forwarded to the socket.
- Existing migration test passes with the new migrations.

### Frontend

- `npm run typecheck` and `npm run lint` pass.
- Manual check in two browser sessions as two users: send/receive, optimistic
  bubble replaced, typing indicator, "Seen", unread badges in dock, nav and
  tab bar, desktop notification while the tab is hidden and none while the
  chat is focused, nothing in DND, mute, reconnect after stopping the backend
  briefly, phone layout at 375px including the keyboard.
